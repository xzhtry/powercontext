1 · 模型与量化

模型 BAAI BGE-small-zh-v1.5（MIT），浏览器 ONNX 版本来自 Xenova/bge-small-zh-v1.5，固定 revision 75c43b0；BERT 4 层、hidden 512、max 512 tokens，CLS pooling + L2 normalize，查询侧加中文检索前缀。运行时 Transformers.js 3.8.1 + ONNX Runtime Web 1.22，推理全部在用户浏览器内完成。

2 · 端侧运行与自动降级

启动时 navigator.gpu.requestAdapter() 探测 WebGPU；可用则显式 device:'webgpu', dtype:'fp16'。适配器缺失、请求失败或 pipeline 初始化异常时，释放失败会话并重建 device:'wasm', dtype:'q8'，顶部同时显示“WASM·INT8 降级”和原因。模型从本地静态目录加载（allowRemoteModels=false），ORT jsep WASM 自托管，COOP/COEP 开启多线程。

验证：正常 Edge 自动选择 WebGPU·FP16；去掉 navigator.gpu 后自动降级，导入/检索/SQL trace 均正常。CSP connect-src 'self'，无任何云端推理 API。

3 · seekdb 数据层与混合检索

集合：每个知识库一个 kb_<id> collection。实测 DDL：

_id varbinary(512) PK、document string、embedding VECTOR(512)、metadata json；FULLTEXT KEY idx_fts(document) WITH PARSER ik (ik_mode="smart")；VECTOR KEY idx_vec(embedding) WITH (DISTANCE=COSINE, TYPE=HNSW, M=16, EF_CONSTRUCTION=200, EF_SEARCH=64)。

注册表：stepkb_collections 保存知识库名/描述/collection/计数；stepkb_docs 保存文档元数据与 content hash（去重）。

混合检索：一次 collection.hybridSearch() 调用，seekdb 的 DBMS_HYBRID_SEARCH.GET_SQL 生成并执行单条 SQL：MATCH(document) AGAINST(...) 做全文召回、cosine_distance(embedding,...) 做向量召回，FULL JOIN 后按 RRF 1/(60+keyword_rank)+1/(60+semantic_rank) 排序。Node 服务不接收两路独立列表、不自行合并；响应中的 hybridTrace.generatedSql 即当次数据库生成的 SQL，界面可展开查看。

增量与刷新：单篇与批量写入 API；批量导入分块一次写入后整批只调一次 refresh_index()（CALL dbms_index_manager.refresh()），再登记为可检索。删除文档/知识库后刷新并清理注册表；切换知识库清空旧结果并按当前 collection 重新加载。

6 · 复现

docker compose up -d（或已有 seekdb 1.4 server）→ pnpm install → pnpm fetch:models → pnpm prepare:assets → pnpm build && pnpm start，打开 http://127.0.0.1:8787。测试：pnpm test、STEPKB_INTEGRATION=1 pnpm test；质量：pnpm fetch:baseline && pnpm eval:quality。模型/运行时/框架均公开可获取；模型清单与 SHA-256 见 docs/model-manifest.json。

端侧：embedding 在浏览器；数据层：seekdb 内完成向量/全文存储与 RRF 混合检索；没有回放服务端预计算，也没有调用云端推理。
