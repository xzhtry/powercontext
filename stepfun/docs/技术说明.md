# StepKB 一页技术说明

**赛题**：端侧 AI 推理性能优化与 seekdb 混合检索 · **分支**：`2026-competition-ecosystem` · **目录**：`stepfun/`

## 1. 模型与量化

| 项 | 内容 |
| --- | --- |
| 模型 | BAAI **BGE-small-zh-v1.5**；ONNX 转换 `Xenova/bge-small-zh-v1.5`，revision `75c43b0`，MIT |
| 结构/输出 | BERT 4 层，hidden 512，max 512 tokens；CLS pooling + L2 normalize；查询侧加 BGE 中文检索前缀 |
| 运行时 | Transformers.js 3.8.1 + ONNX Runtime Web 1.22；**推理全部在浏览器** |
| FP32 基线 | 94,851,877 B（90.5 MiB），仅用于质量对照 |
| FP16 | 47,497,427 B（45.3 MiB），**压缩比 2.00×**，WebGPU |
| INT8 | 24,010,842 B（22.9 MiB），**压缩比 3.95×**，WASM；ONNX dynamic quantization，权重 8-bit/通道 scale |

**质量评测**：同一 20 篇 / 20 分块 / 15 条标注查询、同一分块/前缀，仅替换 ONNX 精度，按相关文档计算 dense ranking。

| 精度 | Recall@5 | nDCG@5 | 相对 FP32 nDCG |
| --- | ---: | ---: | ---: |
| FP32 | 0.8333 | 0.8475 | — |
| FP16 | 0.8333 | 0.8475 | 0.0000 |
| INT8 | 0.8333 | 0.8504 | +0.0029 |

小样本结论：Recall@5 不变，nDCG@5 变化 <0.3 个百分点；INT8 向量相对 FP32 的余弦保真度为 0.98298。逐查询结果见 `evidence/quality-eval.json`。

## 2. 端侧运行与自动降级

页面启动即用 `navigator.gpu.requestAdapter()` 探测 WebGPU。可用时显式 `device:'webgpu', dtype:'fp16'`；适配器缺失或 pipeline 初始化抛错时释放失败会话，自动重建 `device:'wasm', dtype:'q8'`，并在顶部显示 `WASM · INT8 降级` 和具体原因。模型通过本地静态目录加载（`allowRemoteModels=false`），ORT 的 jsep WASM 自托管在 `public/ort`；服务端返回 COOP/COEP 以启用 SIMD 多线程。CSP 限制 `connect-src 'self'`。

验证：正常 Edge 自动选 WebGPU·FP16；用 init script 去掉 `navigator.gpu` 后，降级提示为「当前浏览器没有暴露 navigator.gpu」，导入、检索、SQL trace 均正常（`evidence/fallback.png`）。

## 3. seekdb 使用

- **集合**：每个知识库一个 `kb_<id>` collection；实测 DDL 含 `document STRING`、`embedding VECTOR(512)`、`metadata JSON`、`FULLTEXT KEY idx_fts(document) WITH PARSER ik (ik_mode="smart")`、`VECTOR KEY idx_vec(embedding) WITH (DISTANCE=COSINE, TYPE=HNSW, M=16, EF_CONSTRUCTION=200, EF_SEARCH=64)`。
- **注册表**（同库）：`stepkb_collections` 保存展示名、collection 名、文档/分块计数；`stepkb_docs` 保存文档元数据和 content hash（去重）。
- **混合检索在库内完成**：一次 `collection.hybridSearch()` 调用，seekdb 通过 `DBMS_HYBRID_SEARCH.GET_SQL` 生成并执行单条 SQL：`MATCH(document) AGAINST(...)` 全文召回 + `cosine_distance(embedding, ...)` 向量召回，FULL JOIN 后按 `1/(rank_constant+keyword_rank) + 1/(rank_constant+semantic_rank)` 的 RRF 分数排序。Node 服务不做两路结果拼合；响应里的 `hybridTrace.generatedSql` 就是当次数据库生成的 SQL，前端可直接展开。
- **写入/刷新**：单篇与批量 API；批量导入把 20 篇分块一次写入后**只调用一次** `refresh_index()`（内部 `CALL dbms_index_manager.refresh()`），再登记为可检索。删除文档/知识库后刷新并清理注册表。切换知识库时清空旧结果、按当前 collection 重新拉取。

## 4. 状态与性能优化

- 会话：active KB 存 localStorage，知识库/collection/计数以 seekdb 为准；文档 hash 去重，重复导入跳过。
- 文档分块约 360 字/重叠 60；16 条/批；批间让出主线程；模型/ORT wasm 强缓存；查询模型常驻，不重复加载。
- 轮询 health 也用于展示 seekdb 版本；错误会在 UI 顶部提示。

**实测**（Windows 11 · Edge 156.0.4314.50 · Intel Core Ultra 7 155H / Arc Graphics · 31.5 GiB · seekdb 1.4.0 server；20 篇/20 分块/15 查询；每后端 3 轮，热态 42 条查询取中位数）：

| 指标 | WebGPU·FP16 | WASM·INT8 |
| --- | ---: | ---: |
| 冷启动模型加载 / 预热 | 1,269 / 842 ms | 1,032 / 65 ms |
| 20 篇浏览器向量化 | **732 ms** | 2,197 ms |
| 20 篇写入+刷新（其中刷新） | 881 ms（521） | 761 ms（516） |
| 查询向量化 | 34 ms | 31 ms |
| seekdb 检索 | 13 ms | 8 ms |
| 端到端查询（热 / 首） | 83 / 439 ms | 78 / 159 ms |
| 混合检索 Recall@5 / nDCG@5 | 0.8667 / 0.8787 | 0.9000 / 0.8945 |
| Top-1 命中 | 45/45 | 45/45 |

**优化前后**：WebGPU 批处理 batch=1→16 为 32.26→103.70 块/s（3.21×）；WASM 为 9.17→12.15 块/s（1.33×）。20 篇逐篇刷新 vs 整批一次刷新：12,545→657 ms（**19.1×**，合成 512d 向量隔离模型时间）。浏览器缓存热加载 WebGPU 1,324→880 ms、WASM 999→776 ms。WebGPU 在批量向量化上更快，但单条查询的 GPU 固定开销使小模型单 query 略慢于 WASM；应用仍按题目要求优先 WebGPU，并允许手动切换。原始数据：`evidence/benchmark-summary.md`、`batch-bench-*.json`、`refresh-bench.json`、`load-bench.json`。

## 5. 复现

```bash
cd stepfun
docker compose up -d                 # 或使用已有 seekdb 1.4 server
pnpm install && pnpm fetch:models && pnpm prepare:assets
pnpm build && pnpm start             # http://127.0.0.1:8787
pnpm test                            # chunker / FTS 单测
STEPKB_INTEGRATION=1 pnpm test       # API + seekdb 集成
pnpm eval:quality                    # 需 pnpm fetch:baseline
```

模型、运行时、框架均公开可获取；代码/数据/测试日志全部在 `stepfun/`，模型 manifest 见 `docs/model-manifest.json`。推理位置：浏览器；存储与检索位置：seekdb；未调用任何云端推理 API。
